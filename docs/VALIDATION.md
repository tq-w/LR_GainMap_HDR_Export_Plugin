# 1.0.0.7 验证记录

## 实机环境

macOS 27.0.1、Apple Silicon、Lightroom Classic 15.5.1。两个辅助程序均编译为 arm64+x86_64 通用程序并通过严格签名校验；尚未在 Intel Mac 实机运行。

## SDR 自动识别（1.0.0.7）

在 macOS 27.2.1、Lightroom Classic 15.5.1 环境增加逐张 TIFF 识别。普通 SDR TIFF 不再触发“使用 SDR 色彩编码”错误，而是输出无增益图、SDR 色彩编码的 HEIC。HDR TIFF 继续使用所选 HDR 模式。

合成图验证涵盖 Apple／ISO／PQ／HLG 预设下的自动 SDR 输出、8/10 位、P3/sRGB 色彩配置及亮度／颜色保持；ISO 品质等增益图参数在 SDR 路径忽略。相同预设的 HDR／SDR 并发混合导出、SDR 重名策略均验证。格式损坏、非 TIFF 和 8 位中间 TIFF 仍被拒绝，保留原件与已有输出。

Lightroom 实际关闭 HDR 编辑的照片已通过 UI 完成导出：4000×6000、8 位、Display P3，无 Apple 或 ISO 增益图；未调整照片编辑参数。成功后临时 TIFF 自动清理，原导出目录与选项已恢复。

以下独立增益图品质及 Lightroom HDR 导出的数字来自 1.0.0.6，原 HDR 编码路径保持。

## 品质独立性

同一张 2400 万像素 HDR TIFF，主图品质 70、10 位、增益图宽高各减半：

| 增益图品质 | 增益图 HEVC 数据字节数 |
|---|---:|
| 系统默认 | 601112 |
| 20 | 21420 |
| 50 | 79383 |
| 80 | 311611 |
| 100 | 1648048 |

四档自定义品质的主图 HEVC 压缩数据完全一致。调低主图品质时，固定品质的增益图码流也保持不变。ISO 增益参数、主图位深和图像尺寸一致。品质 80 的下采样 HDR 平均相对误差约 0.067%；这是单个样本的测量，不能作为所有照片或局部区域的误差上限。

另在 Lightroom 内对同一 HDR 照片选择增益图品质 80 和 50，分别得到 281303、129899 字节的增益图 HEVC 数据，主图 HEVC SHA256 完全相同。主图保持 4000×6000、10 位，增益图保持 2000×3000；ISO 参数一致，HDR 高光仍可重建。

这些体积只用于证明参数确实改变增益图编码，不代表不同照片、系统版本或编码器会得到相同大小。

## 编码路径

ImageIO 在本机测试中忽略了辅助图像字典及数据说明中的常规 LossyCompressionQuality。文件级品质、创建选项以及主图品质也不能独立控制辅助图像码流。

因此，独立品质路径将同一标量增益值复制到中性 RGB，用公开系统 HEIC 编码器按指定品质编码，再替换容器内的增益图及相应编码属性。系统使用 8 位 YCbCr 4:2:0；辅助缓冲读取可能不再是单通道，但继续沿用一组标量 ISO 增益参数。主图码流、EXIF/XMP 与 ISO tmap 参数保持不变。

关闭「单独设置」保留原来的单通道系统路径。当前仅支持 ISO HEIC。容器处理只接收本编码路径产生的结构，遇到不支持的结构会报错，并保留中间 TIFF；不会静默丢弃增益图。重建保留内部 idat、隐藏标志和实体组，并避开共享命名空间内的实体组 ID。

## 回归覆盖

- ISO 主图 8/10 位；增益图缩小倍数 1、1.5、2。
- 129×97 奇数尺寸，向上取整；品质 0/100 边界。
- 同一源图、同一尺寸和主图品质下，增益图品质改变实际码流；反向改变主图品质时，增益图码流不变。
- ISO 元数据一致、HDR 高光重建、主图位深与尺寸保持。
- Apple 增益图、PQ／HLG 10 位直接输出与无增益图检查。
- NaN、Inf、越界品质和非 ISO 模式拒绝独立品质参数。
- 中间 TIFF 的格式、位深和色彩编码验证；正常 SDR 自动分流，损坏或无效输入被拒绝并保留。
- 最终 HEIC 自动改名、跳过、覆盖；四路并发和编码途中出现同名文件的保护。
- SIPS 使用相同的最终重名保护；失败不会替换已有 HEIC。
- Lua 语法、选项切换、命令引用和失败时 TIFF 保留。
- Lightroom 实际插件加载、中文面板、HDR 导出、重名改名及跳过。

仓库测试全部使用生成的合成图，不提交实机测试照片。运行 `make test` 可复现合成图回归。
